# 📊 Настройка передачи статистики в leads.tech для VK Mini App

## 🎯 Цель
При клике на оффер внутри VK Mini App статистика должна отбиваться в leads.tech с параметрами:
- **s4** = ID кампании (из макроса `{ref}`)
- **s5** = ID объявления (из макроса `{banner_id}`)
- **s6** = ID пользователя VK (из макроса `{user_id}`)

## 🔗 Формат ссылки для рассылки в боте VK

### ✅ Рекомендуемый формат (с макросами VK)
Используйте этот формат в рассылке бота - VK автоматически заменит макросы на реальные значения:

```
https://vk.com/app53875526#utm_source=vk_mini_app&ref={ref}&ref_source={banner_id}&utm_term={user_id}
```

**Как это работает:**
1. VK заменяет макросы при переходе пользователя:
   - `{ref}` → реальный ID кампании
   - `{banner_id}` → реальный ID объявления
   - `{user_id}` → реальный ID пользователя VK

2. Приложение извлекает параметры из URL:
   - `ref` → передается в leads.tech как **s4** (ID кампании)
   - `ref_source` (который содержит `{banner_id}`) → передается в leads.tech как **s5** (ID объявления)
   - `utm_term` (который содержит `{user_id}`) → передается в leads.tech как **s6** (ID пользователя)

3. При клике на оффер данные отправляются в leads.tech

### Альтернативный формат (если используете другие параметры)
```
https://vk.com/app53875526#ref={ref}&banner_id={banner_id}&user_id={user_id}
```

### Формат с конкретными значениями (для тестирования)
```
https://vk.com/app53875526#ref=12345&banner_id=67890&user_id=111222333
```

## 📋 Как это работает

### Процесс передачи данных:

1. **Рассылка в боте VK**
   - Вы создаете рассылку с ссылкой: `https://vk.com/app53875526#utm_source=vk_mini_app&ref={ref}&ref_source={banner_id}&utm_term={user_id}`
   - VK автоматически заменяет макросы на реальные значения при отправке каждому пользователю

2. **Пользователь переходит по ссылке**
   - VK заменяет макросы:
     - `{ref}` → реальный ID кампании (например: `12345`)
     - `{banner_id}` → реальный ID объявления (например: `67890`)
     - `{user_id}` → реальный ID пользователя (например: `111222333`)
   - Параметры извлекаются из URL приложения

3. **Пользователь кликает на оффер внутри приложения**
   - При клике автоматически вызывается `sendToLeadsTech()`
   - Параметры передаются в leads.tech через наш backend

4. **Backend отправляет данные в leads.tech**
   - **s4** = `ref` (ID кампании из макроса `{ref}`)
   - **s5** = `banner_id` или `ref_source` (ID объявления из макроса `{banner_id}`)
   - **s6** = `user_id` или `userData.id` (ID пользователя из макроса `{user_id}`)

## 🔍 Приоритет параметров

### Для s4 (ID кампании):
1. `ref` (приоритет 1) ⭐ - макрос `{ref}` из рассылки
2. `ref_campaign` (приоритет 2)
3. `utm_campaign` (приоритет 3)

### Для s5 (ID объявления):
1. `banner_id` (приоритет 1) ⭐ - макрос `{banner_id}` из рассылки
2. `ref_ad` (приоритет 2)
3. `ad_id` (приоритет 3)
4. `vk_ad_id` (приоритет 4)
5. `ref_source` (приоритет 5)
6. `utm_content` (приоритет 6)

### Для s6 (ID пользователя):
1. `userData.id` (приоритет 1) ⭐ - реальный ID из VK Bridge
2. `user_id` (приоритет 2) - макрос `{user_id}` из рассылки
3. `utm_term` (приоритет 3)
4. `vk_user_id` (приоритет 4)

## ⚠️ Важные замечания

1. **Параметры передаются в hash (#)**, а не в query string (?)
   - ✅ Правильно: `#ref_campaign=123&ref_ad=456`
   - ❌ Неправильно: `?ref_campaign=123&ref_ad=456`

2. **ID объявления имеет приоритет** - если есть `ref_ad`, он будет использован вместо `ad_id` или `vk_ad_id`

3. **ID кампании имеет приоритет** - если есть `ref_campaign`, он будет использован вместо `ref`

4. **Все параметры логируются** - проверяйте логи для отладки

## 📞 Поддержка

Если параметры не передаются:
1. Проверьте консоль браузера на наличие ошибок
2. Проверьте логи backend: `docker-compose logs backend | grep "Leads.Tech"`
3. Убедитесь, что параметры есть в URL при открытии приложения
4. Проверьте, что пользователь авторизован в VK (для получения user_id)
